Ceaute MVP — build spec
What gets implemented. Part 1 is the token set and every component, each shown once with its states. Part 2 is the screen templates: five layouts that every route in the app is built from. Part 3 fills the templates with real routes using Byuwauk (lashes) and Eluxe (nails). Anything not on this page is out of scope for the MVP.

Yes: one gesture, a bounded list, no typing, no invalid value possible, and it reads as she'd say it ("2h 30m"). Native select on mobile, popover on desktop, 15m to 8h in 15-minute steps. Same control for add-on "adds to time".
Cut from the MVP, on purpose
Bottom tab bars and the floating Menu pill (avatar menu for customers, nav strip for providers). Quick-entry sentence (form only for now; the segment can be added later without changing the form). Book-the-look, briefs, rebook nudges, search-by-date, menu import — all on the Reframes sheet for after launch. Similar providers on the profile (no ranking exists). Skeleton loaders and spinners (server-render). Toasts (in-page notices only). Third font, second accent, shadows on cards, gradients.
Data quirks this spec absorbs
Eluxe's italic-Unicode names (𝑷𝒍𝒂𝒊𝒏 𝑭𝒓𝒆𝒏𝒄𝒉𝒊𝒆𝒔) and emoji strings are stored as typed but rendered normalised — the form strips maths-alphanumeric glyphs to plain letters on save and shows a one-line notice. Byuwauk's "Please note infills…" repeated on five treatments belongs on the group, so the treatment row shows a two-line cap and the notice appears once on the treatments page under the INFILLS label. Add-ons that repeat across every treatment (Eluxe) are a compatibility problem the add-on form solves, not the display.
