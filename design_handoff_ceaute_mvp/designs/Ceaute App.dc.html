Ceaute — every flow
Provider page (locked), customer booking, customer account, provider dashboard. Ceaute ships as a web app first, so frames show a browser address pill instead of a native status bar; the floating provider Menu sits above where Safari's toolbar would be. One vocabulary throughout: white surface, Geist, #8c2b52 on primary actions and links, grey treatment cards, bordered info cards, filled inputs with mono-caps labels. Customers navigate from a top-right menu; providers from a floating Menu pill.

Signature moments — my call
The app is deliberately quiet, so it needs a few places that aren't. Rule I set: the plum block and the full-bleed photo are each spent once per journey, and only where something has actually happened. Confirmed is written as a letter, first-person, because a stranger's home is a real thing to commit to and a receipt table doesn't acknowledge that. Empty states carry the plum instead, so the app has a voice exactly when it has nothing to show. There is no loading screen: pages render server-side with real content, and anything slow (Stripe, availability) shows a skeleton in place, never a splash.

Design decisions against the code
The code's menu drawer becomes a floating pill and popover with the same sections; treatments, groups and add-ons are sub-tabs of Treatments. Add-on compatibility is edited from the add-on, as the code does — the treatment form just says so, and the earlier 1d idea is dropped. The publishing checklist mirrors `publication-readiness.js` item for item. Overview's "Today" and week totals are computed from bookings the dashboard already loads; "Message" on booking detail is a placeholder — provider replies aren't a product flow. Groups can be reordered (display_order exists); the drag handle is the only affordance for it.
